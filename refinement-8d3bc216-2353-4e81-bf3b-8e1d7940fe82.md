# Ajouter une connexion SSO Google a notre logiciel Geofolia

Ajouter une connexion SSO Google à Geofolia via SAML Google Workspace, avec création automatique de compte pour les nouveaux emails et liaison automatique ou manuelle selon la correspondance avec un compte Geofolia existant.

## Brief
### Comportement attendu
- Permettre une connexion SSO Google depuis l'écran de connexion de Geofolia.
- Créer automatiquement un compte Geofolia si l'email Google n'existe pas encore.
- Lier automatiquement le compte Google à un compte Geofolia existant si l'email est identique.
- Proposer une liaison manuelle au premier login si l'email Google ne correspond pas à un compte existant.
- Après authentification, transmettre le jeton Google au front.

### Cas limites
- Email Google identique à un compte Geofolia existant sans SSO : liaison automatique par email.
- Email Google différent d'un compte Geofolia existant : proposition de liaison manuelle au premier login.
- Accès autorisé pour tous les comptes Google, sans restriction de domaine ou de tenant Workspace.
- Conflits potentiels entre comptes Google et comptes Geofolia existants à traiter explicitement.

### Intégrations / APIs / services
- Utilisation de SAML via Google Workspace comme fédération d'identité.
- Déclaration de Geofolia comme application SAML dans Google Workspace / console Google.
- Le fournisseur d'identité est Google; les assertions SAML sont reçues côté backend Geofolia.
- Le front reçoit le jeton Google après authentification.

### Contraintes techniques
- Le backend doit valider les réponses SAML (signature, audience, horodatage) avant de faire confiance à l'email.
- La gestion de session repose sur le jeton Google transmis au front.
- Mise en place du mécanisme de liaison automatique basé sur l'email.
- Mise en place du parcours de liaison manuelle pour les emails différents.

### Données manipulées
- Seul l'email est récupéré depuis le profil Google.
- Ne pas stocker nom, prénom, photo ou domaine Workspace à ce stade.
- Conserver côté Geofolia les informations de liaison nécessaires : email, identifiant Google externe, statut de liaison.

### Risques techniques
- Conflits entre comptes Google et comptes Geofolia existants.
- Ouverture SSO trop large si aucune restriction de domaine n'est appliquée.
- Collecte de données Google supplémentaires non maîtrisée.
- Sécurité des jetons OAuth / tokens mal gérée.

### Impacts perf / sécurité / conformité / observabilité
- Sécurité : validation stricte des assertions SAML et gestion sécurisée des jetons.
- Conformité : minimisation des données en ne collectant que l'email.
- Observabilité : journaliser les connexions SSO, les créations de compte et les liaisons manuelles.
- Performance : impact limité attendu, le traitement SAML étant ponctuel au login.

### Dépendances / migrations
- Dépendance à Google Workspace / Google Identity pour la fédération SAML.
- Configuration de l'application SAML Geofolia dans Google Workspace.
- Migration / liaison des comptes existants à prévoir via l'email.
- Aucune migration de données supplémentaire n'a été explicitement identifiée à ce stade.

### Plan de test / validation
- Tester le login SSO avec un email identique à un compte Geofolia existant : liaison automatique.
- Tester le login SSO avec un email différent : proposition de liaison manuelle.
- Tester la création automatique d'un nouveau compte pour un email inconnu.
- Tester les échecs de validation SAML (signature invalide, audience incorrecte, session expirée).
- Vérifier qu'aucune donnée autre que l'email n'est collectée ou stockée.

## Plan
1. **Cadrer le flux SSO complet** — Décrire précisément le parcours : déclenchement depuis le front, redirection Google, retour SAML, mapping email, création/liaison, transmission du jeton au front.
2. **Configurer Google Workspace pour SAML** — Créer l'application SAML Geofolia, récupérer les métadonnées IdP, configurer l'ACS URL et l'audience, et paramétrer les attributs (email).
3. **Implémenter la validation SAML côté backend** — Ajouter un endpoint de callback SAML qui vérifie la signature, l'audience, l'horodatage et extrait l'email.
4. **Implémenter la liaison automatique par email** — Au retour SAML, rechercher un compte Geofolia avec le même email et lier automatiquement les identités.
5. **Implémenter la liaison manuelle** — Si l'email Google ne correspond pas à un compte Geofolia, proposer une étape de liaison manuelle avant de créer ou associer le compte.
6. **Gérer la transmission du jeton au front** — Définir le mode de transmission sécurisé du jeton Google après authentification et l'intégrer au flux front.
7. **Mettre en place les tests** — Couvrir les cas nominaux et limites : création automatique, liaison auto, liaison manuelle, rejet SAML, erreurs réseau.
8. **Prévoir l'observabilité et la sécurité** — Journaliser les événements SSO et ajouter des alertes sur les échecs de validation ou les tentatives suspectes.

## Code Draft
```
// Backend - réception de la réponse SAML (scaffold Express)
app.post('/api/auth/saml/callback', async (req, res) => {
  const samlResponse = req.body.SAMLResponse;
  const profile = await parseAndValidateSaml(samlResponse); // vérifier signature + audience
  const email = profile.email;

  let user = await findUserByEmail(email);
  if (!user) {
    user = await createUser({ email });
  } else if (!user.googleLinked) {
    await linkGoogleAccount({ userId: user.id, email, googleSubject: profile.subject });
  }

  const token = await createSessionToken(user); // jeton transmis au front
  res.json({ token, user });
});
```
